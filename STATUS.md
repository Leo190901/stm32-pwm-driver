# Project Status

**Last updated:** 2026-11-15
**Current phase:** Driver implementation, step 1 (first PWM output on TIM2_CH1 / PA5)

## Summary

Timer initialization, the public API and the channel configuration
(`PWM_InitChannel`, TIM2_CH1 / PA5 only) are implemented. `PWM_Start` and the
demo in `main.c` are not implemented yet, so the firmware does not produce a PWM signal yet.

## Work log

### 2026-11-15

**`PWM_InitChannel` (`Src/pwm.c`)**
- GPIO: `RCC_AHB1ENR_GPIOAEN`, PA5 `MODER` = 10 (AF), `AFR[0]` AFSEL5 = AF1 (TIM2_CH1).
  Both fields are cleared before being set (read-modify-write).
- Output compare CH1: `CC1S` = 00 (output), `OC1M` = 110 (PWM mode 1), `OC1PE` = 1 (CCR1 preload).
- `CCR1 = ((ARR + 1) * duty_permille + 500) / 1000`, then `EGR.UG` to load the preload.
  UG is only safe because the counter is not running yet; `PWM_SetDuty` must not use it,
  because UG resets CNT for all channels of the timer (REQ-013).
- Validation (REQ-014), in this order, all before the first register write:
  1. `config == NULL` → `PWM_NULL_POINTER`
  2. timer not TIM1..TIM4 → `PWM_INVALID_TIMER`
  3. channel not `PWM_CHANNEL_1..4` → `PWM_INVALID_CHANNEL`
  4. not TIM2 + CH1 (no pin mapping yet, CON-004) → `PWM_INVALID_CHANNEL`
  5. `duty_permille > 1000` → `PWM_INVALID_DUTY`
  - Decision: an unmapped but valid timer/channel returns `PWM_INVALID_CHANNEL` (as the
    `pwm.h` comment says), so `PWM_INVALID_TIMER` keeps meaning "not a supported timer".
  - Check 4 must be timer **or** channel mismatch; otherwise e.g. `{TIM2, CH2}` would configure CH1.
- CCR1 checked on the host at 1 Hz (PSC 244, ARR 65305):

  | Duty   | CCR1  |
  |--------|-------|
  | 0 %    | 0     |
  | 25 %   | 16327 |
  | 50 %   | 32653 |
  | 75 %   | 48980 |
  | 100 %  | 65306 (= ARR + 1, always HIGH) |

- Build OK (GCC 12.2, only the expected FPU `#warning`). The driver functions do not
  appear in the binary yet (FLASH 744 B): `main()` does not call them, so `--gc-sections` removes them.
- `build/` had been configured from `/workspace` (stale CMake cache) and was recreated.
  If `cmake --build build` fails with "rebuilding 'build.ninja'", delete `build/` and configure again.

### 2026-11-14

**Build system**
- Added a CMake build (`CMakeLists.txt`, `cmake/arm-none-eabi.cmake`) so the
  firmware can be built outside STM32CubeIDE, e.g. in the dev container.
  It uses the same flags, defines and linker script as the IDE project and
  produces `.elf`, `.hex` and `.bin` plus a memory usage report.
- Reason: `Debug/makefile` is generated by CubeIDE and contains absolute
  Windows paths, so it can't be used in the container.
- Commit: `8ca4d6b chore: add CMake build for container builds`

**Analysis (verified in this repo, not assumed)**
- *FPU:* The project compiles with `-mfloat-abi=hard` (real FPU instructions,
  no soft-float). `SystemInit` is only declared weak in the startup file and
  never defined, so the linker replaced `bl SystemInit` with a `nop`. Nothing
  writes `SCB->CPACR`, so the FPU stays disabled after reset, and the first
  FPU instruction would cause a UsageFault/HardFault.
  → Decision: duty cycle is an integer (`duty_permille`, 0–1000), so no FPU is needed.
- *Timer clock:* No clock configuration runs at startup, so the MCU stays in
  its reset state: HSI 16 MHz, AHB/APB1/APB2 prescaler /1.
  → TIM1–TIM4 run at **16 MHz** (`PWM_TIMER_CLOCK_HZ`).
  This still needs to be confirmed on hardware (see open items).
- *Pin:* PA5 = TIM2_CH1 via AF1. It also drives LED LD2 on the Nucleo board.

**`PWM_InitTimer` (`Src/pwm.c`)**
- RCC clock enable now uses CMSIS bit names (`RCC_APB1ENR_TIM2EN`, …).
- `CR1.ARPE` is set: ARR is buffered, so period changes apply at the period boundary (REQ-010).
- `EGR.UG` is generated after writing PSC/ARR, so the always-buffered prescaler
  takes effect immediately and the counter is reset.
- The counter is intentionally **not** started here (CEN stays 0), see `PWM_Start`.
- PSC/ARR math checked on the host. All TC-001 frequencies are within REQ-006 (±1 %):

  | Frequency | PSC | ARR   | Actual          | Error     |
  |-----------|-----|-------|-----------------|-----------|
  | 1 Hz      | 244 | 65305 | 1.000002 Hz     | +0.0002 % |
  | 1 kHz     | 0   | 15999 | 1000.000 Hz     | 0 %       |
  | 10 kHz    | 0   | 1599  | 10000.000 Hz    | 0 %       |
  | 100 kHz   | 0   | 159   | 100000.000 Hz   | 0 %       |

**API (`Inc/pwm.h`)**
- `float duty_cycle` was replaced by `uint16_t duty_permille` (0–1000, 0.1 % steps).
- Added constants: `PWM_FREQ_MIN_HZ`, `PWM_FREQ_MAX_HZ`, `PWM_DUTY_MAX_PERMILLE`,
  and `PWM_CHANNEL_1`–`PWM_CHANNEL_4`.
- Added status codes: `PWM_INVALID_CHANNEL` (4) and `PWM_INVALID_DUTY` (5).
- Declared `PWM_InitChannel()` and `PWM_Start()`; they are not implemented yet.
- Commit: `6a2166f feat: add preload/update event to timer init and extend PWM API`
