# STM32 PWM Driver – Software Requirements Specification

**Version:** 1.0 (Draft)  
**Target MCU:** STM32F401RE  
**Language:** C  
**Implementation:** Direct register access (CMSIS)

## 1. Purpose

The purpose of this project is to develop a reusable PWM driver for the STM32F401RE microcontroller.

The driver shall support multiple hardware timers and PWM channels, configurable frequencies and duty cycles, and independent channel control.

## 2. Scope

The driver shall support the following hardware timers:

- TIM1
- TIM2
- TIM3
- TIM4

Each timer shall support channels CH1–CH4, subject to the available physical pin mappings.

PWM signals shall be generated by the timer hardware without continuous CPU intervention.

## 3. Functional Requirements

| ID | Requirement |
|---|---|
| REQ-001 | The driver shall support TIM1, TIM2, TIM3 and TIM4. |
| REQ-002 | The driver shall support all four PWM channels of each supported timer. |
| REQ-003 | Different timers shall support independently configurable PWM frequencies. |
| REQ-004 | Each PWM channel shall support an independently configurable duty cycle. |
| REQ-005 | The driver shall support PWM frequencies from 1 Hz to 100 kHz. |
| REQ-006 | The calculated PWM frequency shall deviate by no more than ±1% from the requested frequency, excluding clock-source tolerance. |
| REQ-007 | The duty cycle shall be configurable from 0% to 100%, inclusive. |
| REQ-008 | The generated duty cycle shall deviate by no more than ±0.5 percentage points from the requested value. |
| REQ-009 | Duty-cycle changes during operation shall take effect at the next regular PWM period boundary without unintended pulses. |
| REQ-010 | Frequency changes during operation shall be synchronized to a regular PWM period boundary without unintended pulses. |
| REQ-011 | Each PWM channel shall be individually startable and stoppable. |
| REQ-012 | A stopped PWM channel shall output a defined LOW level. |
| REQ-013 | Stopping one PWM channel shall not interrupt other active channels of the same timer. |
| REQ-014 | Invalid input parameters shall return an error status without modifying the existing PWM configuration. |

## 4. Implementation Constraints

| ID | Constraint |
|---|---|
| CON-001 | The PWM driver shall use direct peripheral register access through CMSIS definitions. |
| CON-002 | The PWM driver shall not depend on STM32 HAL for PWM configuration. |
| CON-003 | The implementation shall target the STM32F401RE microcontroller. |
| CON-004 | Only valid timer-channel and GPIO alternate-function mappings shall be used. |

## 5. Verification

The requirements shall be verified using software tests and hardware measurements with a logic analyzer.

| Test ID | Requirements | Verification |
|---|---|---|
| TC-001 | REQ-005, REQ-006 | Measure PWM frequencies at 1 Hz, 1 kHz, 10 kHz and 100 kHz. |
| TC-002 | REQ-007, REQ-008 | Measure duty cycles at 0%, 25%, 50%, 75% and 100%. |
| TC-003 | REQ-003 | Generate different frequencies simultaneously on two timers. |
| TC-004 | REQ-002, REQ-004 | Configure different duty cycles on channels of the same timer. |
| TC-005 | REQ-009, REQ-010 | Change frequency and duty cycle during operation and inspect transition periods. |
| TC-006 | REQ-011–013 | Start and stop individual channels and verify the output levels and unaffected channels. |
| TC-007 | REQ-014 | Provide invalid parameters and verify error reporting and unchanged configuration. |
| TC-008 | REQ-001, REQ-002, CON-004 | Verify supported timer-channel mappings and test accessible outputs. |

## 6. Open Design and Verification Items

The following details shall be resolved during software design:

- Define the supported GPIO pin mapping and document pin conflicts.
- Define the driver API and initialization sequence.
- Define how multiple channel updates on the same timer are coordinated.
- Determine how synchronized frequency changes are implemented.
- Verify the achievable frequency and duty-cycle tolerances for the supported timer clock configurations.
- Define the handling of shared timer resources when multiple channels are active.
- Establish the detailed acceptance criteria for dynamic updates and channel stop behavior.
